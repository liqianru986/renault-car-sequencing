# Renault Car Sequencing 项目全流程与面试复习

## 1. 项目定位

本项目复现 ROADEF 2005 Renault Car Sequencing 工业赛题。静态部分解决单日车辆排序；动态扩展部分处理计划执行过程中发生的紧急订单、选装工位临时降产和冻结窗口。项目目标不是只得到一个序列，而是建立从数据读取、业务建模、算法求解、独立评估、官方 Checker 到实验分析的完整链路。

静态赛题接口保持原样。动态事件、动态评估和动态求解器位于独立模块中，避免把作品集扩展逻辑混入官方 Benchmark。

## 2. 静态赛题业务背景

同一条汽车生产线混流生产不同颜色和选装配置的车辆。喷涂车间希望相同颜色尽量连续，以减少换色清洗；但连续同色批次不能超过 `PaintBatchLimit`。装配工位希望高负荷选装车辆均匀分布，以 N/P 滑动窗口表达：任意连续 P 辆中，带某选装件的车辆不能超过 N 辆。

比例约束是软约束，按超出数量累计违法；最大连续同色批次是硬约束。赛题实例给出三种目标顺序：

- `EP → RAF → ENP`：高优先级比例违法、颜色切换、低优先级比例违法；
- `EP → ENP → RAF`；
- `RAF → EP → ENP`。

目标按实例指定顺序进行字典序比较；官方 Checker 使用固定位权将目标向量映射为分数。

## 3. 数据流与工程流程

```text
官方实例目录
  → RoadefParser
  → ProblemInstance（车辆、颜色、N/P、D-1、目标顺序）
  → Greedy / Gurobi / ALNS
  → SequenceSolution
  → RenaultEvaluator
  → RoadefSolutionWriter
  → 官方 exeCarSeq Checker
  → CSV、JSON、收敛轨迹与汇总报告
```

### 3.1 Parser

Parser 分别读取 objectives、paint batch limit、ratio constraints、D-1 vehicles 和 D vehicles，并校验表头、车辆唯一性、option flags 维度和目标 rank。

### 3.2 Domain

`ProblemInstance` 是只读问题对象；`Vehicle`、`RatioConstraint` 和 `ObjectiveSpec` 表达领域实体。算法只依赖领域对象，不直接读取文件。

### 3.3 Evaluator

所有算法共享同一个 Evaluator，避免每个求解器自行解释指标。Evaluator 检查车辆集合完整性，计算跨日颜色切换、最大同色批次、HPRC/LPRC 窗口违法、目标向量和官方分数。

## 4. 初始解：目标感知 Greedy

SeqRank 只代表 Renault 提供的原始排序字段，不是优化算法。ALNS 默认使用目标感知 Greedy：

1. 按 `(paint_color, option_flags)` 聚合相同车型；
2. 逐位置选择下一车型；
3. 计算加入候选后新增的 HPRC/LPRC 违法；
4. 用剩余车辆选装密度和 N/P 比率计算动态紧迫度；
5. 按实例目标优先级比较候选；
6. 检查最大连续同色批次；
7. 以确定性规则打破并列，再还原真实车辆 ID。

动态紧迫度用于避免“当前不违法、但把难排车辆全部留到最后”的短视行为。

## 5. Gurobi 静态 MILP

### 5.1 车型聚合

颜色和完整 option flags 相同的车辆聚合为一个 `VehicleType`。二进制变量 `x[t,p]` 表示位置 p 是否安排车型 t，显著减少车辆级排列变量。

### 5.2 主要约束

- 每个位置恰好一个车型；
- 每种车型安排次数等于需求量；
- 车型与颜色变量联动；
- 相邻位置颜色变化变量；
- 任意 `PaintBatchLimit+1` 窗口不能全部同色；
- 每条 N/P、每个滑动窗口设置非负违法变量；
- D-1 尾部车辆作为参数进入跨日窗口。

### 5.3 目标和 Warm Start

按官方固定位权最小化目标。Greedy 类型序列写入 Gurobi `.Start` 属性作为 MIP Start。60秒结束时记录状态、Incumbent、Best Bound、MIP Gap、节点数和运行时间。

## 6. ALNS 与 VFLS

### 6.1 ALNS 主循环

ALNS 从 Greedy 解开始，循环执行：

```text
局部强化
  → 自适应选择 Destroy
  → Greedy/Regret-2 Repair
  → 完整评估
  → 模拟退火接受
  → 更新算子奖励与权重
```

Destroy 包含 Random、Violation-focused 和 Same-color；Repair 包含 Greedy Insert 与 Regret-2。

### 6.2 增量 VFLS

实现三种局部移动：

- `Swap(i,j)`；
- `Insert(i,j)`，同时覆盖 forward/backward insert；
- `Reflection(i,j)`，反转闭区间。

增量状态保存各约束窗口负荷、各约束违法总数、颜色切换数和超长颜色批次数。区间移动使用 option 差量前缀和，只更新与变化区间相交的窗口；颜色只更新受影响边和批次。局部搜索结束且确有改善时才调用一次完整 Evaluator。

VFLS 尝试比例约为 `Swap:Insert:Reflection = 7:2:1`，部分距离从约束 denominator 中抽取。采用初始强化与每10轮周期强化，避免局部搜索挤占全部 ALNS 时间。

## 7. 静态实验设计

- 数据：Set A 16个、Set X 19个，共35个官方实例；
- 算法：SeqRank、Gurobi、ALNS；
- Gurobi与ALNS统一时限：60秒/实例；
- 固定随机种子：42；
- Gurobi MIP Gap目标：1%；
- ALNS：Destroy上限8辆、候选插入位置30、Regret候选6、VFLS 100次/每10轮；
- 输出均由官方 Checker 复核；
- 比较必须在同一实例内部进行，不能跨不同目标顺序直接比较绝对分数。

最终全量数字由 `analyze_results.py` 从 CSV 自动生成，避免手工复制错误。

## 8. 动态场景建模

### 8.1 事件

- 在原车辆集合中加入三辆紧急订单；
- 位置40前已执行，额外冻结20辆，因此前60位不可改变；
- HPRC3 在位置80–150临时从原能力调整为1/5；
- 原计划来自无扰动静态ALNS 60秒解。

### 8.2 动态指标

- 原赛题 HPRC、LPRC、Paint 和官方口径分；
- 临时能力违法数；
- 被移动原订单数；
- 总位置偏移；
- 平均位置偏移；
- 最大位置偏移；
- 冻结前缀是否保持；
- 紧急订单最终插入位置。

### 8.3 动态目标

第一层最小化临时能力违法。第二层联合考虑：

```text
official_score_weight × 原赛题分数
+ moved_vehicle_weight × 移动车辆数
+ position_shift_weight × 总位置偏移
```

冻结窗口、颜色批次上限、移动预算和总偏移预算作为硬约束。

## 9. 动态 ALNS

冻结前缀不参与 Destroy/Repair。新增 Capacity-focused Destroy，优先移除临时降产窗口中占用目标工位能力的车辆；Capacity Swap 优先寻找同色、但不需要该选装件的车辆换入窗口，减少能力违法且尽量不增加颜色切换。Repair 同时考虑静态质量和计划偏移。

## 10. 动态 Gurobi

动态模型使用车辆级 `x[v,p]`，原因是车型聚合无法表达具体订单的位置偏移。模型包含：

- 车辆—位置排列；
- 冻结位置等式；
- 静态颜色和N/P约束；
- 分时段临时N/P违法变量；
- 每辆原订单的绝对位置偏移变量；
- 是否离开原位置的二进制变量；
- 临时能力优先、质量与稳定性次优的多目标。

动态扩展不属于官方赛题，因此不能用原 Checker；使用扩展 Evaluator，并分别保存原赛题指标和动态指标。

## 11. 当前动态案例结果

无扰动静态基准：目标向量 `(0,39,51)`，官方分3951。

| 指标 | 插单后未重排 | 动态ALNS | 动态Gurobi |
|---|---:|---:|---:|
| 临时能力违法 | 1 | 0 | 0 |
| 官方口径分 | 44269 | 15266 | 4272 |
| 移动车辆数 | 0 | 33 | 3 |
| 总位置偏移 | 0 | 622 | 8 |
| 平均位置偏移 | 0 | 1.86 | 0.02 |
| 最大位置偏移 | 0 | 157 | 6 |
| 冻结前缀有效 | — | 是 | 是 |

该结果说明动态Gurobi在此中等规模案例上更擅长严格控制计划扰动；动态ALNS虽然消除了临时能力违法，但稳定性仍有明显调优空间。

## 12. 高频面试问题

### 为什么不用SeqRank做初始解？

SeqRank是原始排序字段，不感知目标和约束。目标感知Greedy利用当前窗口负荷和剩余选装紧迫度，能显著降低起点HPRC，为60秒元启发式节约搜索时间。

### 为什么既有ALNS又有VFLS？

ALNS通过大范围移除重插跳出局部最优；VFLS高频探索Swap/Insert/Reflection小邻域，用于局部强化。两者负责不同搜索尺度。

### 增量评估为什么重要？

完整评估每个候选需要扫描整条序列和所有窗口。增量评估只更新移动影响范围，使相同时间内能尝试更多局部变换。实现后通过200次随机混合移动逐步与完整Evaluator对齐。

### 为什么静态MILP聚合、动态MILP不聚合？

静态目标只关心车型属性，因此同类型车辆可交换。动态目标包含具体订单相对原计划的位置偏移，车辆身份不可消除，所以使用车辆级变量。

### 为什么60秒？

485辆三种子实验中，最好解分别出现在42–52秒；30秒后仍有稳定改善。60秒兼顾结果质量、35实例总实验成本和可复现性。

### 动态模型中的“计划稳定性”是什么？

它不是主观描述，而是由移动车辆数、总/平均/最大位置偏移和冻结前缀共同刻画。移动数量反映受影响订单范围，位置偏移反映调整强度，冻结窗口表达现场不可逆执行边界。

### 为什么不能宣称动态结果通过官方Checker？

官方Checker只认识原车辆集合和原N/P约束。紧急订单和分时段能力是项目扩展，必须由扩展Evaluator验证；混用Checker会造成虚假结论。

## 13. 结果表述边界

- 只报告实际完成并保存的实验；
- Gurobi在60秒内通常是可行解而非最优解，应同时报告状态与Gap；
- 随机算法单种子全量结果只能称固定种子基线；若写稳定性，应引用单实例多种子实验；
- 动态案例是公开实例上的模拟事件，不称真实工厂上线；
- 不把官方分跨不同目标顺序直接平均比较。
